# 广州话词典 OCR 脚本修改说明

## 修改概述

已将 `OCR_openrouter_gz-dict.py` 从现代粤语词典OCR脚本改造为广州话词典重新OCR脚本。

## 主要修改内容

### 1. 脚本目的更新
- **原目的**: OCR现代粤语词典
- **新目的**: 重新OCR广州话词典，补充缺失的波浪线（～）和生僻字

### 2. 配置修改
- **输入图片文件夹**: `./input/广州话词典/`
- **已有OCR文本**: `./input/广州话词典（提取文字）.txt`
- **输出文件**: `./output/广州话词典_重新OCR_输出.txt`
- **处理页面范围**: 第121-659页（共539页）

### 3. 新增功能

#### 3.1 加载已有OCR文本
```python
def load_existing_ocr_text(ocr_file_path: str) -> str
```
- 读取已有的OCR文本文件作为参考

#### 3.2 构建页码索引
```python
def build_page_index(full_ocr_text: str) -> dict
```
- 识别已有OCR文本中的页码标记（单独成行的数字）
- 构建页码到行号的映射字典
- OCR文本第1-539页对应实际书页第121-659页

#### 3.3 提取页面上下文
```python
def extract_page_context(full_ocr_text: str, page_num: int, page_index: dict, context_lines: int = 80) -> str
```
- **使用精确的页码标记**提取对应页面的内容
- 从当前页码标记提取到下一个页码标记（或文件末尾）
- 最多提取80行或3000字符

### 4. Prompt优化

#### 4.1 重点强调内容
- **波浪线符号（～）**: 在例句中代替词头，之前OCR完全遗漏
- **生僻字识别**: 特别列出需要识别的生僻字
  - 𢱕、𢳂、𡃇、𠾴、𤶸、𠼭、㨢、𩗴、䭰
  - 语气词如"㗎"等

#### 4.2 参考例子更新
使用广州话词典实际格式的10个例子：
- 【包剪𢱕】bɑo1 jin2 deb6 (𢱕，杜合切)
- 【𢳂】bed1 (毕)
- 【𡃇】bei6 (弊)
- 等等...

#### 4.3 已有OCR文本作为参考
在每次OCR请求中，都会包含：
- 当前页码信息
- 该页对应的已有OCR文本片段
- 要求AI以已有文本为基础进行校正和补充

### 5. 处理流程改进

```
1. 加载完整的已有OCR文本
2. 对于每张图片：
   a. 提取该页对应的已有OCR文本片段
   b. 将图片、页码、已有文本一起发送给AI
   c. AI基于已有文本进行校正，重点补充波浪线和生僻字
   d. 实时保存结果
```

## 使用方法

### 前置条件
1. 确保 `.env` 文件中已设置 `OPENROUTER_API_KEY`
2. 确保以下文件/文件夹存在：
   - `./input/广州话词典/` (包含页面_121 到 页面_659 的PNG图片)
   - `./input/广州话词典（提取文字）.txt` (已有OCR文本)

### 运行脚本
```bash
python OCR_openrouter_gz-dict.py
```

### 输出
- 输出文件: `./output/广州话词典_重新OCR_输出.txt`
- 每页结果实时保存，包含：
  - 文件名和页码
  - Token使用统计
  - OCR识别的文本内容

## 关键改进点

1. **以已有OCR为基础**: 不是从头OCR，而是在已有结果基础上校正和补充
2. **重点关注遗漏**: 特别强调之前遗漏的波浪线和生僻字
3. **精确页码定位**: 识别已有OCR文本中的页码标记，精确提取每页内容作为参考
4. **上下文参考**: 为每页提供对应的已有OCR文本片段（最多80行）作为参考
5. **实时保存**: 每处理完一页立即保存，避免中断导致数据丢失

## 页码映射说明

已有OCR文本包含明确的页码标记（单独成行的数字）：
- OCR文本页码：1-539
- 实际书页页码：121-659
- 映射关系：OCR页码 + 120 = 实际页码
- 页码标记示例：第62行显示"1"（第121页），第133行显示"2"（第122页）

## 注意事项

1. **页码识别**: 脚本会自动识别已有OCR文本中的页码标记，确保精确匹配
2. **Token限制**: 每页prompt包含较长的参考文本，注意API token消耗
3. **处理时间**: 539页图片处理需要较长时间，建议分批处理或使用后台运行

## 技术栈

- **AI模型**: Google Gemini 3 Flash Preview (通过OpenRouter)
- **图片处理**: PIL/Pillow
- **API客户端**: OpenAI SDK (兼容OpenRouter)
