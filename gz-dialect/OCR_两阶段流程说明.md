# 两阶段 OCR 流程说明

## 流程概述

为了高效且准确地完成 OCR，我们采用了两阶段 Flash 模型处理流程：

```
图片 → [阶段1: Flash OCR] → IPA结果 → [阶段2: Flash转换] → 粤拼结果
         识别文字和IPA                    IPA转粤拼
```

## 阶段详情

### 阶段 1：Flash 模型 OCR（IPA 标音）
- **模型**：`google/gemini-3-flash-preview`
- **任务**：识别图片内容，输出 IPA 标音
- **特点**：
  - 速度快（约 2-3 秒/图片）
  - 成本低
  - 能够识别大部分内容
- **输出**：带 IPA 标音的 OCR 结果

### 阶段 2：Flash 模型智能转换（IPA+调值 → 粤拼+调号）
- **模型**：`google/gemini-3-flash-preview`
- **任务**：转换为香港语言学学会粤语拼音（jyutping）+ 调号
- **输入**：阶段 1 的 OCR 结果（IPA + 调值）
- **核心策略**：⭐ **优先根据汉字反推粤语读音**
  - 作为粤语专家，根据词条汉字判断正确读音
  - 不是机械转换 IPA，而是智能判断
  - 如果 IPA 明显错误，以汉字读音为准
- **转换内容**：
  - **调值 → 调号**：
    * 55 → 1 (陰平甲)
    * 53 → 1' (陰平乙，用撇号区分)
    * 35 → 2 (陰上)
    * 33 → 3 (陰去)
    * 21 → 4 (陽平)
    * 13 → 5 (陽上)
    * 22 → 6 (陽去)
    * 入声：5→1, 3→3, 2→6
  - **IPA → 粤拼**：使用香港语言学学会方案
  - **变调**：保留 * 标记（如：33*35 → 3*2）
- **特点**：
  - 智能识别，而非机械转换
  - 保持所有格式标记（【】、<>、丨等）
  - 输出标准化粤拼（便于查询和处理）

## 优势分析

### 1. 成本极低
- 两个阶段都使用 Flash 模型
- Flash 模型价格极低（远低于 Pro）
- 506 张图片的总成本预计非常经济

### 2. 速度很快
- 阶段 1 (OCR)：2-3 秒
- 阶段 2 (转换)：1-2 秒
- 总计：3-5 秒/图片
- 506 张图片预计：约 25-40 分钟

### 3. 输出标准化
- 直接输出粤拼（jyutping）标音
- 粤拼是标准化的罗马拼音系统
- 更易于后续处理和查询
- 避免 IPA 特殊符号的显示和输入问题

### 4. 分工明确
- 第一阶段专注于识别
- 第二阶段专注于格式转换
- 每个阶段任务单一，更容易成功

## Token 使用估算

假设每张图片：
- Flash: ~800 tokens
- Pro: ~1500 tokens
- 总计: ~2300 tokens/图片

506 张图片：
- 总计: ~1,163,800 tokens
- 成本估算（根据 OpenRouter 定价）：
  - Flash: 极低成本
  - Pro: 需要查看具体定价

## 注意事项

1. **API Key 配置**：确保 `.env` 文件中已设置 `OPENROUTER_API_KEY`
2. **网络稳定**：建议在稳定的网络环境下运行
3. **错误处理**：脚本会自动捕获错误并继续处理下一张图片
4. **输出保存**：结果实时写入文件，即使中断也不会丢失已处理的内容
